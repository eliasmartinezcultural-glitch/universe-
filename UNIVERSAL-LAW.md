# CHANAR — EL UNIVERSO VIVO
## LEY UNIVERSAL DEL PROYECTO
### V2 — BLOQUEO DE FUNCIONALIDAD Y ESTRUCTURA

**Estado: CONGELADO**

Este documento tiene prioridad sobre cualquier modificación futura del proyecto.

---

## 1. PRINCIPIO SUPREMO

**El Universo Vivo no es una aplicación convencional.**

Es una experiencia audiovisual interactiva sobre San Patricio del Chañar.

La experiencia debe sentirse como un **universo que responde**, no como una herramienta que el visitante utiliza.

La simplicidad visible y la profundidad invisible son principios permanentes.

---

## 2. QUEDA BLOQUEADO

Desde V2 quedan congelados:

- la arquitectura general de la experiencia;
- el funcionamiento central;
- el modelo de interacción;
- la lógica de evolución del territorio;
- la progresión VIENTO → AGUA → TIERRA → VIDA → CAMINOS → PERSONAS → PUEBLO;
- la lógica de emergencia del mundo;
- el sistema Canvas + HTML + JavaScript;
- la ausencia de backend;
- la ausencia de dependencias externas obligatorias;
- la experiencia sin menús ni paneles funcionales;
- la interacción directa mediante toque, movimiento, arrastre y cursor;
- la adaptación básica a dispositivos móviles y PC;
- la idea de que las acciones del visitante producen transformaciones visibles;
- la relación causal entre territorio, vida, caminos, personas y estructuras;
- la filosofía de interfaz mínima.

**Nada de esto se reemplaza, simplifica, fragmenta, reorganiza ni rediseña estructuralmente sin una decisión explícita de crear una nueva generación del proyecto.**

---

## 3. QUÉ SÍ PUEDE CAMBIARSE

A partir de este momento solamente se permite trabajar sobre:

### DISEÑO
- iluminación;
- atmósfera;
- composición;
- tipografía;
- microanimaciones;
- partículas;
- profundidad;
- escala visual;
- transiciones;
- texturas;
- ritmo;
- cinematografía;
- lenguaje visual;
- refinamiento gráfico.

### EXPERIENCIA
- recorrido;
- sensación de descubrimiento;
- sorpresa;
- emoción;
- inmersión;
- percepción del tiempo;
- narrativa ambiental;
- calidad de las transiciones;
- relación entre lo que hace el visitante y lo que percibe.

### RECORRIDO COMPLETO
Se puede mejorar cómo se vive la experiencia desde:

**entrada → descubrimiento → interacción → evolución → conexión → aparición del pueblo → cierre → continuidad.**

No se modifica la arquitectura funcional que sostiene ese recorrido.

### MULTIDISPOSITIVO
Se permite adaptar profundamente la presentación para:

- teléfono pequeño;
- teléfono grande;
- tablet;
- notebook;
- escritorio;
- pantallas grandes;
- orientación vertical;
- orientación horizontal;
- diferentes densidades de píxeles;
- diferentes capacidades gráficas.

La adaptación debe preservar la misma experiencia conceptual.

## 4. REGLA DE NO REGRESIÓN

Toda mejora futura debe cumplir:

**MEJOR DISEÑO ≠ NUEVA FUNCIONALIDAD**

**MEJOR EXPERIENCIA ≠ NUEVA ARQUITECTURA**

**MEJOR RECORRIDO ≠ CAMBIO DEL SISTEMA**

Si una modificación requiere alterar la funcionalidad o estructura bloqueada, **NO SE REALIZA dentro de V2**.

---

## 5. REGLA DE CAPAS

El proyecto seguirá esta separación:

**NÚCLEO CONGELADO**
- funcionamiento;
- estructura;
- lógica;
- interacción;
- evolución.

**CAPA EVOLUTIVA**
- diseño;
- experiencia;
- recorrido;
- presentación;
- adaptación multidispositivo.

Toda futura intervención debe intentar vivir exclusivamente en la segunda capa.
